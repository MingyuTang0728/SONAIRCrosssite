Visual localisation and scan planning

Start with a flat rectangular reference surface of known dimensions. Select its four corners, rectify the image, generate a raster path and review visual anomaly candidates. Curved parts need a separate depth or multi-view reconstruction pipeline.

1 · Load the inspection image

Select four corners in order: origin (0,0), +X (W,0), opposite (W,H), +Y (0,H). Choose corners so X cross Y points out of the surface toward the camera (for a front view: lower-left, lower-right, upper-right, upper-left). Use an undistorted image. The four points must lie on the same physical plane.

2 · Resolve the planar metric map

No metric mapping yet. Corner selection is user-assisted localisation, not automatic 6D pose estimation.

3 · Generate the inspection path

Path points are camera optical-centre positions in the part frame, not executable TCP poses.

4 · Review visual candidates

Local dark-contrast baseline highlights potential marks or scratches. Reflections, texture and dirt can also trigger it. It cannot establish material defects or detect hidden flaws. Candidate coordinates inherit the planar assumption.

What is exported and what remains

The JSON bundle contains source image SHA-256, selected corners, homography, part dimensions, calibration ID, raster points, optical direction, algorithm settings, candidate review labels and candidate positions. Images remain on your computer. The bundle is not URScript and does not move the robot. It needs calibrated base-to-part and TCP-to-camera transforms, IK, joint limits, collision checking, approach/retract motions and local approval before execution. Preview time excludes acceleration and settling.

Robot transform chain: T_base_TCP = T_base_part · T_part_camera · inverse(T_TCP_camera). The current export provides optical-centre positions and optical-axis directions only; rotation about that axis is still to be specified. The IMU is for orientation and motion-quality monitoring, not a stand-alone source of metric position.

Input contract and scoring

CSV fields: sequence_id,t_s,domain,condition,pred_qx,pred_qy,pred_qz,pred_qw,ref_qx,ref_qy,ref_qz,ref_qw,latency_ms. Use simple unquoted identifiers. Time must increase strictly inside each domain/sequence. Domain is sim or real. Quaternion norms must be within 0.001 of one. Values must be finite. Latency must be nonnegative. CSV is rejected on any invalid row; rows are never silently removed.

Per-frame angular error = 2 acos(|q_pred · q_ref|), in degrees. Report per-sequence RMSE, macro-average sequence RMSE per domain, and pooled frame P95. Transfer gap = real macro RMSE minus sim macro RMSE; interpret only when condition sets and model settings match. There is no arbitrary combined score or industrial pass threshold.

4 · 3D reconstruction and automatic scan path

Carry the camera on the arm, sweep it around the work area, fuse the depth views into the robot base frame, isolate the component and raster over its measured surface at a constant standoff.

This builds a height field of what the camera can see from above. It is not SLAM and it is not CAD registration. A part with undercuts, or a job needing full 360° coverage, needs multi-side capture and a real surface reconstruction — this pipeline would mislead you there rather than fail visibly.

4.1 · Hand-eye calibration

Where the camera sits relative to the tool flange, as a 4×4 matrix in row-major order. Accuracy here bounds everything downstream: a 2° rotation error puts the cloud 10 mm out at 300 mm standoff, and unlike depth noise it does not average away over views.

What each backend module does

ur_telemetry.py — RTDE on 30004 for the full field set, falling back to the 30003 primary interface if RTDE cannot be negotiated. The panel shows which one is live, because a number with no stated source is not a measurement.

ur_control.py — URScript on 30002 for motion, IO, payload and tool; dashboard on 29999 for power, brakes, program and protective-stop recovery; RTDE inputs for the speed slider, which has no URScript equivalent.

scan3d.py — deprojection, voxel fusion, RANSAC plane removal, connected-component clustering, PCA localisation and height-field path planning. numpy only.
