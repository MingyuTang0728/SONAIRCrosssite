1 · The board

Count inner corners, not squares — or press Read the board for me and don't count at all. A calib.io board labelled 18×25 has 24×17 inner corners: the label counts squares, and one row and column of them has no inner corner.

Never enter a smaller size than the board really is. A grid will still be found — an arbitrary patch of the middle — and it lands somewhere different in every shot, which ruins the calibration while every number on screen still looks right.
A board with small squares needs pixels to match. One square has to land on roughly 15 pixels or more, so for a 7.5 mm board set the colour stream to 1280×720 or higher on the Camera page and keep the board filling most of the frame.

What is on the flange

The simulated arm's payload is built from these numbers. A campaign recorded without them is compared against a simulation carrying nothing, and afterwards that difference cannot be told apart from the sim-to-real gap it contaminates. Weigh the carrier — sensor, bracket, cable and all — on a kitchen scale; that is accurate enough. Zero is a fine answer if the flange really is bare. Enter it once per build; re-enter it after any refit.
—

The benchmark campaign —

The planned campaign: 6 elbow speeds × 3 arm configurations × 3 trajectory types = 54 conditions, 5 repeats each over 3 sessions. Teach the three configurations once, then run one session at a time. A session that stops can simply be run again — runs already done and checked are skipped, and any run whose file failed its check is recorded again. Run the imu mount cal job from the list below once the carrier is fitted, and again after the refit.

Finding the three configurations

Put the arm somewhere you know is safe — by hand with Hold to hand-guide, or with the pendant — then press Suggest from here. Three positions are worked out from where the arm is, each one checked so that every run's elbow travel keeps the tool at least 3 cm inside the safe envelope. Then drive to each one with Hold to move there: the arm moves slowly (about 9° a second) and only while you hold the button; let go and it stops at once. When it arrives, look at it, and if you are happy press Teach here for that row in the table below. Keep the emergency stop within reach.

Identification set (E1) —

Training data for the people who use the benchmark: every joint of the arm is moved, not only the elbow, so a simulator can be tuned on these runs without ever seeing the runs it is scored on. Each joint is swept from slow to fast in turn (about a minute each), then all six move together in three different patterns at each configuration. It is recorded twice: with the carrier alone, then with a known extra mass bolted on. About 20 minutes each. The three configurations above must be taught first.

Every motion is worked out and checked against the safe envelope before anything moves; one that would leave it is turned the other way or made smaller, and if it still does not fit it is left out and you are told why. The arm moves faster here than when you drive it to a position — up to 0.8 rad/s at one joint — so watch the first run with a hand on the emergency stop. For the second set: bolt on the mass, weigh carrier and mass together, save that under What is on the flange, and set the same payload on the pendant.

Faster than guided moves (up to 0.8 rad/s at one joint). Watch the first run with a hand on the emergency stop. For Set 2, weigh carrier + mass, save it under What is on the flange and set the same payload on the pendant.

Set this to match where the arm actually is before you start. It is one of the three factors results are grouped by, and a run labelled mid workspace that was taken with the arm extended is a mislabelled cell nothing downstream can detect.
